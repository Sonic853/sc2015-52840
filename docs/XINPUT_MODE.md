# 修订号12：Xbox输入、开机组合键与网页映射

本轮增加**PC端有线XInput输入模式**，以及两个模式均可访问的WebHID配置接口。已经过原生协议/映射/USB模型、网页、Edge模拟HID和实际ARM构建验证；**修订号12尚未刷入实物验证Windows枚举和手柄开机动作**。修订号11的实物结果不代表本轮已通过硬件验证。

## 使用

1. 刷入 `build/xiao/SCReceiver-xiao-s140-7.3.0.uf2`；上电默认Steam原生模式，保留已有绑定。
2. 接收器连接到PC后，**同时按住左背键与Steam键开机**，建立私有无线连接后继续同时保持至少约300ms，再将两键全部松开。
3. 固件只在新会话开始的3秒窗口内接受该组合。严格要求同一份新鲜、已认证输入中两键都按着；仅左背、仅Steam、提前松开或已使用很久之后按组合不触发。
4. USB会断开并以Xbox模式重新枚举；射频会话继续运行。一次持键只请求一次，直到两键都松开前抑制组合输入，USB重置生成的中性报告不算真实松键。
5. **断开并重新连接Type-C恢复Steam模式**。重新上电也从Steam模式启动；Xbox模式不写入Flash。主机普通USB bus reset不切回Steam。
6. 手柄若处于BLE模式，先用A+Steam恢复私有接收器模式；本接收器不接收BLE手柄输入。

这里的“开机组合”是在新RF会话的早期输入里识别，不是新增了手柄原厂开机分支；连接窗口无法严格区分手柄冷启动和某些RF重连。已有绑定恢复后才允许组合触发，新配对待保存时不会触发。

## 默认Xbox映射

|物理输入|Xbox输出|
|---|---|
|左摇杆|左摇杆X/Y|
|左摇杆按压|L3|
|左触控板位置|按压时输出八方向十字键；中心死区内释放|
|左触控板按压|默认作为十字键触发条件，不额外映射按钮；松开即释放方向|
|右触控板位置|右摇杆X/Y；松开触摸回中|
|右触控板按压|R3|
|左背键|R3|
|右背键|L3|
|A/B/X/Y、LB/RB|同名按钮|
|左前/右前小键|Back/Start|
|Steam|Guide；开机切换组合期间被消费|
|LT/RT|模拟扳机；压到底的数字开关默认输出对应255值|

只有一个USB XInput gamepad。组合切换使用触发槽；网页切换后选取第一个新鲜输入槽，在线期间其他槽不抢占，断开后才选择其他输入来源。250ms没有新鲜输入时输出中性状态；未更新的复用坐标最多保留200ms。

模式转换不会让SC2015凭空拥有第二个物理摇杆。独立坐标恢复、按压位与八方向判定见 [COORDINATE_DECODING.md](COORDINATE_DECODING.md)。

## 网页配置

“输入模式与Xbox按键配置”面板支持：

- Steam/Xbox切换，等待完整Feature回复消费后执行USB重新枚举。
- 16个物理按钮各自映射到无、A/B/X/Y、LB/RB、Back/Start/Guide、L3/R3、四个D-pad方向或LT/RT。
- 左摇杆、右触控板摇杆的软件死区；左板十字键径向阈值。
- 右板X/Y反转；左板默认按压后触发十字键，也可取消该选项改为触摸触发。
- 读取、填写默认值、保存并回读配置。填写默认值不自动写Flash。

按键配置单独保存，Type-C重连后仍保留。两个物理键可映射到同一按钮；相反D-pad方向同时出现时输出中性方向。

“按压后才触发”是无已保存配置时的固件默认值，也是网页“填入默认配置”的值。若已有保存的触摸触发配置，在网页勾选该项并保存即可应用新选择。

首次切换到Xbox身份后，浏览器可能需要再次点击“连接 / 授权接口”；授权该身份的vendor HID后可在Xbox模式下修改配置并切回Steam。后续已授权设备可以自动重新连接。网页串行化自己的操作，但另一进程仍可能修改配置；旧配置token写入会被拒绝，需重新读取。

## USB布局与Windows驱动

|模式|设备身份|接口|
|---|---|---|
|Steam|`28de:1142`|原有IF0键鼠、IF1..4槽HID|
|Xbox|开发用 `28de:1143`|IF0 XInput；IF1原键鼠HID（不发送桌面输入）；IF2..5配置/原始状态HID|

Xbox的IF0为 `FF/5D/01`，20字节输入，IN81/OUT02，4ms轮询。Microsoft OS 1.0字符串 `MSFT100` 与Extended Compatible ID `XUSB10`只在Xbox模式提供，作用于IF0；其余HID留给系统HID驱动和WebHID。

没有使用 `045e:028e`作为整个复合设备的身份：本机 `xusb22.inf`按该硬件ID可接管整个设备，不能据此保证额外网页HID仍可用。该INF同时列有 `USB\MS_COMP_XUSB10`兼容匹配；本轮采用按接口绑定的实现。此静态依据及字节/链接检查仍不能替代真实Windows枚举测试。`28de:1143`是工程开发身份，不是产品ID分配声明。

五个Adafruit HID对象只注册一次。切换时detach、等待、重建描述符并按相同HID实例顺序重新加入，避免反复begin耗尽实例；Xbox的USB接口号相对HID实例号多1，EP0槽号换算同步调整。主机新RESET完成前暂缓发送输入。

当前实现输入和配置；Xbox OUT中的LED/rumble数据被接收并隔离，不当作Steam Feature命令执行。**本轮没有Xbox震动转换、Xbox主机认证或主机兼容承诺。**

## 手柄初始化与持久化

- Xbox：向已绑定会话排入81清数字映射，以及87设置packet version49=2、左右触控板模式7/8=7，避免桌面鼠标/键盘行为。
- Steam新连接/恢复：85恢复数字映射、8E恢复默认设置，让接收器失电但手柄仍开机的场景能恢复。Steam随后可正常设置自己的配置。
- 两条初始化消息按整批容量检查入队，带会话generation校验；不覆盖host的本地回复、查询owner或Feature版本。
- 映射配置使用 `0xe9000/0xea000`两页，48字节版本化记录、generation、CRC32、最后提交字；只有显式保存才写入。无有效记录时用默认值，不自动擦写。
- 绑定页仍是 `0xeb000/0xec000`。链接ASSERT和UF2检查把应用上限收紧到 `0xe9000`，配置/绑定均不包含在应用UF2里。

## FD / FE协议v1

均为64字节Feature payload，不含hidapi额外的Report ID零字节。仅在已验证XIAO修订号>=12上使用。

### FD：模式

- 读取：`FD 00`。
- 切换：`FD 05 4D 4F 44 45 mode`（`MODE`加0=Steam/1=Xbox）。
- 回复：`FD 62 1 revision status current requested owner flags`，其余保留0。
- owner为0..3或FF无来源；flags.bit0配置持久化可用、bit1切换/导入忙、bit2重插恢复Steam。
- SET处理只准备回复；完整GET的状态完成、且版本仍匹配时才提交切换请求。短GET、未完成GET、被覆盖的回复及USB reset取消的未完成请求不会触发切换。

### FE：映射

- 读取：`FE 00`。
- 写入：`FE 29 01 expectedCRC32LE wireConfig24`。
- 回复：offset0..5=`FE,62,1,revision,status,24`；8..11配置CRC32；12..35为wireConfig；其他保留0。
- wireConfig：byte0版本1；byte1 flags（bit0右X反转、bit1右Y反转、bit2左板需要按压）；bytes2..17为16个映射目标；18..19左摇杆死区，20..21右板死区，22..23十字键阈值（均LE16）。
- 映射目标ID：0无、1A、2B、3X、4Y、5LB、6RB、7Back、8Start、9Guide、10L3、11R3、12上、13下、14左、15右、16LT、17RT。
- 物理输入顺序与网页一致：A/B/X/Y/LB/RB/Back/Start/Steam/左背/右背/摇杆按压/左板按压/右板按压/左扳机到底/右扳机到底。
- 两种回复status：0成功、1参数错误、2旧配置token、4忙、6保存失败。配置保存失败保持旧运行映射；相同配置不重复写Flash。FE失败通过自己的状态返回，不冒充旧F0绑定Flash计数。

## 验证范围

当前测试覆盖严格双键/超时窗口/时钟回卷、按住跨模式不重复、真实输入观察与USB合成释放隔离、左右坐标复用/反向同时操作/八方向/点击条件、断开与过期中性、配置破坏/截断/旧token/保存失败、短/中止GET、不随USB reset退模式、物理unplug回Steam、HID对象不累积，以及网页授权/保存/双向切换流程。

真实验收还需：Windows能获得XInput状态、网页HID与XInput共存、手柄开机组合首包、重插Type-C、左右板/摇杆同时操作、Flash保存后重新上电，以及原Steam模式配对/触觉回归。构建和测试结果见 [VERIFICATION.md](VERIFICATION.md)。
