# 修订号22：滑动右摇杆与Xbox / PS5 / Switch独立布局

## 网页设置

1. 升级接收器至能力修订号22，打开网页22.0，在**Steam模式**连接配置接口。
2. 展开“独立按键布局与触控板”，在**编辑布局**选择Xbox、PS5或Switch。这是在编辑对应配置，不会立即切换USB模式。
3. 调整16键映射、左右死区、左板方向阈值/斜向角度、右板反转和按压条件。
4. 在“右触控板模拟方式”选择：
   - **固定中心**：沿用原行为，触点相对触控板中心的位置决定摇杆偏转，停在边缘持续推杆。
   - **滑动模式**：滑动方向和速度决定推杆；在板上任意位置落指都先定位，不跳杆。即使仍处于中心右侧，向左滑也产生向左推杆。
5. 调整曲线及参数，点击**保存按键配置**。只保存当前选择模式的布局及右板参数。切到其他编辑模式可保留本页草稿；刷新网页不会保存草稿。
6. 最后用“目标输入模式”切换USB，或使用对应开机组合，验证游戏内效果。三个模式的配置分别持久化，重启后保留。

PS5编辑器显示×/○/□/△、L1/R1/L2/R2、Create/Options/PS；Switch编辑器显示B/A/Y/X、L/R/ZL/ZR、−/+/Home。这些是各目标的实际输出名称，物理输入仍是SC2015的A/B/X/Y等。

**全局设置**仍包括“记住输入模式”、右板滑动触觉强度和Lizard左板滚轮强度。修改全局记住模式可能令另一布局旧草稿的token失效，此时读取该布局后再编辑保存。Lizard维持自己的固定键鼠映射。

## 参数、范围与建议起点

|参数|范围|默认|含义|
|---|---|---|---|
|模拟方式|固定中心 / 滑动|固定中心|升级保持原有手感，需主动启用滑动|
|曲线指数γ|0.50–3.00；网页步长0.05|1.00|线性1.00、精细2.00、快速0.50，也可自定义|
|满杆滑速|20–2000原始坐标单位/ms|200|越小越灵敏；原始中心到边缘约32767单位，200对应约164ms滑过半径达到满杆|
|平滑时间常数|0–40ms|10|0关闭；越大越平滑，也会增加响应延迟|
|输出反死区|0–500‰|0|有效移动时补上最小输出；100‰即10%，过大可能产生明显起步跳动|
|去抖速度|0–50原始坐标单位/ms，必须小于满杆滑速|2|忽略小幅噪声；过大会吃掉慢滑|

位置死区3500等仅用于固定中心模式，滑动时禁用该编辑框并保留其值。图表横轴为去抖后的归一化速度，纵轴为输出摇杆幅度；不包含游戏自己的曲线、死区或加速度。

建议先用**滑动＋线性1.00＋满杆200＋平滑10ms＋反死区0＋去抖2**。先在游戏中调整镜头灵敏度，再按需降低满杆速度；只有确认慢滑被游戏死区吃掉时，逐步增加反死区。精细曲线不保证在所有游戏里更好，因为游戏可能还会再施加一次非线性。

## 实际算法

1. 仅新认证无线输入更新坐标。RADIO接收记录自带时间戳，主循环将其换算到连续队列微秒时钟并传入协议观察路径；不是用USB发送间隔或批量处理间隔估速。
2. 首次触摸、抬手再触摸、长间隔或会话变化重新建立锚点。相同时间戳不生成第二份速度；下一份有效采样包含总位移。
3. 最短4ms窗口累计坐标差，以实际采样时间计算`vx=dx/Δt`、`vy=dy/Δt`，单位为原始坐标/ms。
4. 可选时间归一化指数平滑，`alpha=1-exp(-Δt/tau)`，分别更新两轴速度。
5. 取速度向量长度`s`，按去抖速度`n`和满杆速度`f`归一化：`r=clamp((s-n)/(f-n),0,1)`。
6. 无有效速度时输出严格为0；否则输出幅度为`a+(1-a)*r^γ`，`a=反死区/1000`，沿速度向量方向输出。径向限制防止斜向超过满杆，最后应用该布局的X/Y反转。
7. Xbox使用16位轴，PS5转换为8位轴和对应Y方向，Switch转换为其12位轴范围；保持各自原有报告格式。

没有轨迹球惯性：抬手立即清零；停手通过平滑回中。距最新采样或最新超过去抖阈值的有效运动超过50ms时，计算结果强制归零；USB主机将在后续成功的报告中看到该结果。这是输出计算门限，不是对物理传输延迟的保证。

过旧的队列采样会被丢弃并重新定位，避免批量处理形成短时间内满杆尖峰。USB reset/resume、模式/配置变化、RF generation变化和owner切换清理滑动历史。R3点击和触觉反馈仍走既有独立路径。

参考[Steam Input Source Modes](https://partner.steamgames.com/doc/features/steam_controller/input_source_modes)的Mouse Joystick、响应曲线和最小输出语义；本实现为可验证的幂函数/指数滤波设计，不声称复刻Steam客户端内部源码。游戏自身的最高转速仍限制快速滑动的效果。

## 配置迁移与存储

- 旧SCXM v1/v2（48字节）和v3（56字节）均可读取。原共享布局在内存中复制到Xbox、PS5、Switch三套，右板方式均为固定中心；v3触觉强度、记住模式及启动选择保留。
- 新SCXM v4共144字节：header12；三套36字节布局位于12/48/84；last/once位于120/121；全局触觉宽度位于122/124；126..135保留为0；CRC32位于136，提交字位于140。
- 仍在`0xe9000/0xea000`双页轮换，先写另一页、校验后最后写提交字，绑定页独立。首次实际保存或消费一次性启动选择时写入v4；单纯读取不会强制写Flash。
- 较旧固件不认识v4，降级后可能使用默认配置；不要将旧固件的默认显示误认为新配置仍被读取。

## FE协议扩展（仅修订号22起）

原FE空参数查询与操作1保留v1格式，读写Xbox的旧24字节映射；操作2仍读写全局触觉强度。旧客户端保存Xbox布局会保留其滑动参数及另两套布局。

新操作：

```text
读取：FE 02 03 profile
保存：FE 2A 04 profile token_le32 profile_wire[36]
profile：1=Xbox，2=PS5，3=Switch
```

回复为64字节：`FE 3E 02 revision status 24 profile 00 token_le32 profile_wire[36] zero[16]`。这里`24`是十六进制36字节。

36字节布局体：byte0=2；byte1保持旧flags编码（bit3是全局记住模式的投影）；2..17为按键；18/20/22为三个LE16阈值；24为模式0/1；25保留0；26/28/30/32/34依次为γ×100、满杆速度、平滑ms、反死区‰、去抖速度，均LE16。

token为`CRC32(profile单字节 + 36字节布局体)`，绑定目标模式；不能把Xbox token用于PS5。其他模式布局变化不会使当前token失效，但全局记住模式变化会影响三套token。保存前验证范围、token与busy状态；失败不应用，成功后回读核验。每次保存基于当前完整配置替换单套，保留其他布局和触觉强度。

## 验证

- 260条原生专项断言：4/8/16ms采样等效、同处理时刻不同接收时刻、方向反转、落指、静止、50ms过期、时间回卷、曲线oracle、径向饱和、三套布局、旧记录迁移、逐字节损坏、跨模式token、失败保存及旧客户端/触觉写入隔离。
- 生产CCM→观察回调→Xbox USB IN验证两个排队样本以原8ms间隔估速，重复认证包不更新速度；PS5/Switch输出编码也有专项检查。
- Node及真实Edge模拟HID覆盖独立保存/重启、草稿保留、目标按钮名称、曲线参数、旧固件门控与中英文切换。
- 本轮未刷写硬件，实际游戏响应、触控噪声和滤波手感仍需实测。产物与当前测试计数见 [VERIFICATION.md](VERIFICATION.md)。
