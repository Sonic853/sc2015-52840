# 修订号5：活动槽Feature回复与网页UF2入口

后续实物报告已确认修订号5网页连接和按键输入。Steam详情初始化兼容性由 [修订号6](STEAM_COMPAT.md)继续处理。

## 实物报告与可复现问题

用户提供的`sc2015-diagnostics (2).json`显示修订号4、activePipes=6、一个已保存绑定、H=2接受4次、最后接入结果9。ACK安排/READY/完成均4100，说明恢复接入已成功。活动逻辑槽0却在网页Feature错误后被移除，导出只剩离线槽1–3；不能把接口缺失解读为无线断开。

软件回归复现：先缓存手柄type2/3的无线Feature回复，再发本地B4/F0，旧版`peekFeature()`仍优先返回无线缓存。本地F1–F6绑定回复也可能被异步无线回复覆盖。回归在修复前失败，修复后通过；这能解释错误回复，但不单独证明实物中每一次USB挂起的原因。

## 回复和消费规则

- 本地查询/绑定事务与无线回复使用独立缓存；当前命令决定GET的数据来源。
- 本地GET不消费无线缓存；异步无线回复不覆盖本地回复或改变其版本。
- 重新发送无线命令只有命令和完整参数均与缓存对应请求一致才命中；其他请求清除不相干旧回复。
- GET未完成占位符不清除等待状态，重复SET不会因此重复排队。
- USB回调在SETUP复制已发布版本；使用TinyUSB nRF5未占用的弱`dcd_edpt0_status_complete()`钩子，在TinyUSB报告状态阶段完成后入队消费。短GET和没有完成回调的GET不消费；过期版本不能清除更新的回复。nRF5x DCD在安排状态阶段时合成完成事件，不能将该钩子当作独立的物理ACK证据。
- 无线join/断开清理不清除当前本地USB命令，使B2等仍能在关闭自身无线会话后正确回显。
- 对已断开槽发B3不再生成虚假的已连接通知。

网页对可恢复的回复不匹配保留槽、输入监听和最近状态，标注查询异常并在下次刷新重试。真正挂起的接口隔离，不继续排队；显式重新授权可重开。组诊断可回退到其他健康槽。物理拔出仍移除接口。

## F9进入UF2模式

这是本工程XIAO扩展，不能发送给原版Valve接收器。F7固件修订号>=5声明支持。

请求是64字节无Report ID的Feature payload：

```text
f9 04 55 46 32 21 00 ... 00
      U  F  2  !
```

WebHID的Report ID参数单独传0。响应为`f9 02 status 01`补零，status0接受、1参数错误、4绑定导入尚未结束；末字节01指UF2大容量存储模式。

只发送SET不会重启。成功回复必须经过完整64字节GET及TinyUSB状态阶段完成回调，且版本仍匹配；之后主循环等待100ms，暂停RADIO、detach USB，调用Seeed核心`enterUf2Dfu()`。nRF5x的状态完成回调是DCD合成事件；100ms留给主机完成传输/释放句柄，实际枚举仍需实测。该入口写`NRF_POWER->GPREGRET=0x57`并软件复位。本命令不写Flash、不修改持久绑定；未保存的新绑定和其他RAM会话随重启丢失。

网页先重新读取目标身份及修订号，读到成功回复才结束该接收器全部槽的控制和自动保存范围。其他接收器和原版身份来源保留。绑定导入busy、旧固件或USB失败不会显示成功。

## 使用与实物复测

1. 首次安装修订号5仍通过双击RESET进入UF2盘；复制当前构建的XIAO UF2。
2. 部署更新后的`web/`，连接目标并确认“固件更新”显示支持网页UF2。
3. 保持已绑定手柄在线，反复刷新F0/F7/F8/B4，确认活动槽保留且能读取输入；如仍失败，下载新诊断JSON。
4. 先保存待保存绑定，点击“进入 UF2 刷入模式”，检查目标USB断开及UF2盘出现。
5. 将同一工程UF2复制进盘，重新连接网页并检查持久绑定数，按Steam验证恢复。

原生ASan、Node、真实Edge加模拟HID和ARM编译已覆盖上述软件路径；尚未由代理在物理XIAO验证UF2盘枚举或此修订的USB改动。最新构建hash及测试数字见 [VERIFICATION.md](VERIFICATION.md)。
